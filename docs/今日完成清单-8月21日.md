# 今日完成清单（8/21）· AI Agent 测试平台重构

> 从「扁平 MVP」升级到「通用内核 + 场景插件」架构，落地主控 + 5 子 Agent，接入双插件 + 三真实数据源，全程 26 项单测保护，端到端跑通。

---

## ✅ 交付物

**1. 通用内核**（三个子系统，与测试域完全解耦）
- `core/tools/`：`Tool` 抽象 + `ToolRegistry`（schema 与执行绑定，子 Agent 工具集隔离）
- `core/plugins/`：`TestPlugin` ABC（5 扩展点）+ dataclass 数据模型 + `PluginRegistry`
- `core/agents/`：`LLMAgent` 基类（手动工具循环 + adaptive thinking + 网关鉴权）+ 5 子 Agent + `Coordinator` 主控串行编排

**2. 两个场景插件**（证明「换插件即换测试域」）
- `plugins/acoustic/`：声学，3 工具（adb/logcat/serial）+ 7 检查点 + 分层定位 prompt，原 MVP 逻辑零丢失
- `plugins/lamp/`：AI 台灯，2 **真解析器**（iperf3 吞吐 + autocall 通话 CSV）+ WiFi/通话知识库

**3. 三个真实数据源**（没有一个是编的）
- 声学 logcat：真实 PCM 资源竞争故障序列
- iperf3：8/19 真实 LL10 压测日志（26.5Mbps / 88 峰值重传 / 3 秒断流）
- autocall CSV：你自己写的通话重启缺陷复现工具产出，解析器已接入

**4. 演示脚本 + 测试**
- `examples/demo.py`（仅分析，快）、`demo_pipeline.py`（完整 5 段）、`demo_plugin_swap.py`（插件切换核心卖点）
- 26 项单测全绿（工具系统/插件契约/iperf3+call 解析器数字校验）

**5. 面试讲解材料**
- `docs/面试讲解-AI测试平台.md`：电梯陈述 + 架构全景 + 设计决策 + 真实代码逐行讲解 + autocall 硬核踩坑 + demo 脚本 + 高频追问标准答法 + 诚实边界

## 🔑 核心亮点（面试脱口而出）

**架构骨架**：5 扩展点 ↔ 5 子 Agent 一一对应。结果分析是皇冠明珠（真 LLM 多轮工具循环），执行/用例是确定性（保证可复现）。

**通用性证明**：同一个 `Coordinator.run()`，只换插件名，测试域从声学切到 WiFi/通话，内核零改动。两个插件都实现同一个 `TestPlugin` 契约。

**保真度取舍**：结果分析=真 LLM 多轮；需求/报告=真 LLM 单轮；用例设计+执行=确定性不烧 LLM。这个「哪里该用 AI、哪里不该用」的判断本身就是工程成熟度。

**三真实数据**：iperf3 真数字（26.5 / 88 / 3）、autocall 真工具（vchat 线程三态 53/54/91、MAC 锁定防漂移、日志块缓冲踩坑）、logcat 真故障序列。

**手动工具循环**（默写级）：`stop_reason == "tool_use"` 循环，assistant 的 tool_use 块原样追加历史，工具结果作为 user 消息回传，max_rounds 兜底防失控。

## 🛠️ 重构踩坑（真实工程细节）

**包 vs 模块命名遮蔽**：旧 `core/tools.py` 模块与新 `core/tools/` 包冲突，Python 优先导入包，`DISPATCH` 符号找不到。解决：删旧模块，只留包。

**adaptive thinking API 变化**：Opus 4.8 旧的 `budget_tokens` 写法会 400 报错，改用 `thinking={"type":"adaptive"}`。

**网关鉴权兼容**：公司走讯飞网关（`one.iflytek.com`），用 `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`，不是官方 `ANTHROPIC_API_KEY`。代码两种都兼容，`_build_client()` 按 config 分支。

**autocall 五大踩坑**：① log.txt 块缓冲致假阳性 → 改 /proc 实时信号；② vchat 线程数精确三态；③ MAC 锁定防多台漂移；④ 挂断键坐标随界面变；⑤ 双通道交叉确认重启（uptime 归零 或 PID 变）。
