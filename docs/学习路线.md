# 学习路线 · 边做真项目边学框架

> 配套：`DEVELOPMENT_PLAN.md`（总计划）、`docs/UPGRADE_DESIGN.md`（细化设计）、`UPGRADE_PROGRESS.md`（进度）。
> 生成日期：2026-09-23
> 定位：这不是一份"框架教程合集"，而是一张**学习地图**——把每个该学的技术栈，钉在本项目具体的开发阶段上。等你做到那个阶段，我们**用真实功能代码当教学材料**，不写一次性的教学 demo。

---

## 0. 核心原则：真实代码即教学参照

你不需要"先学完框架再来开发"，也不需要我"专门写一套教学代码"。两者合一：

- **学习 = 开发该阶段的真实功能**。学 Pydantic 就在 P8 里用它重写决策 schema；学向量检索就在 P4 里给 golden-set 接上。写出来的都是项目要用的真代码。
- **真代码里带"教学注释"**：我在关键处用 `# 学习点：...` 前缀标注"这里为什么这样用这个框架"，你回头看代码就是看讲解。
- **先自研跑通、再考虑上轮子**（重要节奏）：多数阶段先手写把机制吃透、单测跑绿，再引框架替换或增强。这样你同时拥有两个故事——"我理解底层机制" + "我会用生态轮子"。这正是这个项目最值钱的地方，别为了用框架打乱它。

### 判断某个环节要不要上轮子的一条标准

- **领域逻辑 + 控制流** → 保持自研（这是你的差异化：分层定位、复测循环、置信度门槛、审计目录）。
- **纯基础设施** → 复用轮子（重试退避、可观测面板、向量检索、配置分层——手搓性价比低）。

## 1. 我们每次"学习 + 开发"会话的固定套路

进入某个阶段、要学对应框架时，按这个流程走（你不用记，我会主动带）：

1. **大白话心智模型（对话里，5-10 分钟）**：我先用类比把"这框架到底在干嘛"讲清楚，不占开发时间。
2. **直接上真功能**：用它开发该阶段的真实代码，边写边讲"这一行对应刚才的哪个概念"。
3. **教学注释**：真代码里关键处加 `# 学习点：` 注释，作为你事后复看的参照。
4. **动手小练习（3-5 个）**：基于刚写的真代码，给你几个"改改看会怎样"的练习（如"把这个字段改成必填，看校验怎么报错"）。
5. **记一笔**：你在文末「学习记录表」打勾 + 写一句心得或卡住的点，下次接着深入。

> 你随时可以说"这里再讲细一点"或"这个先跳过"，节奏你定。

## 3. 逐个技术栈 · 小白入门卡

> 每张卡：**一句话是什么 / 心智模型 / 为什么学 / 本项目落点 / 第一步动手 / 学完能讲的面试点**。真正的深入在做到对应阶段时进行。

### 3.1 Pydantic ⭐⭐⭐（P8，最先学）

- **一句话**：用 Python 类型注解定义"数据长什么样"，它负责**校验 + 转换 + 生成 schema**。
- **心智模型**：把一个普通 dataclass 升级成"会自己检查合法性、还能吐出 JSON Schema"的智能数据模型。你给字段标类型和取值范围，非法数据进来它直接报错，不用你手写一堆 `if`。
- **为什么学**：几乎所有现代 Python/LLM 项目的地基（FastAPI、instructor、LangChain 都建在它上面）。对本项目，它能**自动生成你现在手写的 `DECISION_SCHEMA`**——你写个类，`.model_json_schema()` 就吐出等价的 JSON Schema，还白送 enum 越界校验。
- **本项目落点**：P8 用 `BaseModel` 定义"决策模型"（`confidence`/`evidence_sufficiency` 等字段），替换 `subagents.py` 里手写的 dict schema。
- **第一步动手**：把 `DECISION_SCHEMA` 用一个 Pydantic 类重写，对比手写 dict 少了多少代码、多了什么校验。
- **面试点**：「决策 schema 我用 Pydantic 定义，字段类型和 enum 由它校验，schema 直接从模型生成，避免了手写 JSON Schema 的漂移和拼写错误。」

### 3.2 LangGraph ⭐⭐⭐（重点专项，见 §4）

见下方 §4 单独展开——因为你最不熟，且它和你的 Coordinator 是直接对照。

### 3.3 tenacity ⭐⭐（P1 Harness）

- **一句话**：给任意函数加"失败自动重试"的装饰器库。
- **心智模型**：你在函数上贴一个 `@retry(...)` 标签，规定"哪些异常要重试、重试几次、每次等多久（指数退避 + 随机抖动）"，它全帮你处理。你不用自己写 `for attempt in range(3): try... sleep...`。
- **为什么学**：重试/退避是所有网络调用的通用刚需，学一次到处用。配合 **pybreaker**（熔断：连续失败就快速失败一段时间，不空烧）。
- **注意**：Anthropic SDK 本身已带 `max_retries` 和类型化异常（`RateLimitError`/`APITimeoutError` 等）——P1 要先搞清"SDK 已经重试了什么"，tenacity 补的是**跨多次 LLM 调用的阶段级**策略。
- **本项目落点**：P1 的 `core/harness/`——用 tenacity 实现 `RetryPolicy`，而不是从零手写退避循环。
- **第一步动手**：给一个"前两次抛异常、第三次成功"的假函数贴 `@retry`，打印每次的等待时间，看指数退避的效果。
- **面试点**：「我的 harness 层区分可重试/致命/可降级三类错误，用 tenacity 做指数退避 + jitter，pybreaker 做熔断，避免故障时空烧 token。」

### 3.4 Langfuse ⭐⭐（P5 可观测性）

- **一句话**：开源的 LLM 可观测平台——把每次 LLM 调用的 prompt/输出/token/耗时/成本记录下来，给你一个看板。
- **心智模型**：像给你的 Agent 装了个"飞行记录仪"。每次调模型自动打点，你在网页看板上能看到"这次运行花了多少 token、哪个 Agent 最慢、哪轮工具调用出错"。可以自托管（Docker 起一个）。
- **为什么学**：LLM 可观测性是当前很热的岗位技能；顺带接触 OpenTelemetry（OTel）这套通用观测标准（同类还有 Arize Phoenix、OpenLLMetry）。
- **本项目落点**：P5——用装饰器/回调接入你现有的 `on_event` 事件流，几乎零侵入。**注意分工**：Langfuse 负责"看"（trace/成本展示），你的 `RunBudget` 预算硬闸负责"管"（越界止损）——预算逻辑保持自研，是你的亮点。
- **第一步动手**：本地 Docker 起一个 Langfuse，跑一次 mock，在看板上看这次运行的 token 瀑布图。
- **面试点**：「运行产出结构化 trace（token/耗时/工具分布），我用 Langfuse 做可视化；成本控制我自研了 token 硬闸 + 墙钟止损两道预算闸，越界诚实收尾。」

### 3.5 向量检索三件套 ⭐⭐（P4 档二）

- **一句话**：把文本变成向量、按"语义相似"检索——RAG 的核心。
- **心智模型**：现在你的 golden-set 检索是"关键词精确/LIKE 匹配"（换个说法就搜不到）。向量检索是把"症状描述"变成一串数字（embedding），语义相近的文本数字也相近，于是"六次唤醒后吞唤醒"能匹配到"多轮交互后唤醒失效"，哪怕用词不同。
- **三件套**：
  - **embedding 模型**：文本→向量。本地用 `sentence-transformers`；或用 **Voyage AI**（Anthropic 官方推荐的 embedding，自家无 embedding 模型）。
  - **向量库**：存向量 + 相似检索。首选 **sqlite-vec**（接你现有 SQLite，保住"JSON 是唯一真相源、索引可重建"的设计）；最易上手的是 **chromadb**（几行代码起步）。（注：老教程里的 `sqlite-vss` 已被同作者的 `sqlite-vec` 取代。）
  - **检索/重排**：查最相似的 top-k，可选再重排。
- **本项目落点**：P4 档二——给 `GoldenSetIndex` 加 `search_semantic()`，与现有关键词 `search()` 结果融合排序。档一（工具化+打分）先手写吃透，再上档二。
- **第一步动手**：用 sentence-transformers 把 golden-set 里几条 symptom 编码成向量，手算两两余弦相似度，直观感受"语义相近=数字相近"。
- **面试点**：「golden-set 检索我做了两档：档一关键词打分（可解释、零依赖），档二向量语义检索兜住换词问题；JSON 始终是唯一真相源，向量索引可从 JSON 重建。」

### 3.6 MCP Python SDK ⭐⭐（P6）

- **一句话**：Anthropic 主推的"给 LLM 接工具/数据"的开放协议，官方有 Python SDK。
- **心智模型**：MCP 是"工具的 USB 接口"。你把平台能力（生成用例、跑测试、查 golden-set）包成一个 MCP server，任何支持 MCP 的客户端（Claude Code、Cursor 等）插上就能用——"换公司=换一组 MCP 配置"。
- **为什么学**：你本来就在用 Claude，MCP 是自家协议，强正相关加分项。官方 SDK 里的 **FastMCP**（已并入官方 python-sdk）让你几行代码起一个 server。
- **本项目落点**：P6——把 P3 的用例生成、P1 的测试执行、P4 的 golden-set 查询暴露为 MCP tools。依赖 P2 适配层已就位。
- **第一步动手**：用 FastMCP 写一个只有一个工具（如 `query_golden_set`）的最小 server，在 Claude Code 里连上调一次。
- **面试点**：「平台能力我用 MCP 对外暴露，跨工具复用；这是'带去别的公司'最现代的答案——换环境只换 MCP 配置，不改核心代码。」

### 3.7 配角（了解 / 用到再学）

- **pydantic-settings**（P2）：分层读配置（环境变量 > 文件），做"换公司=换配置"。
- **GitPython / tree-sitter**（P3）：GitPython 读 diff；tree-sitter 真正解析代码语法树、追调用链，替代正则猜"代码影响范围"。
- **instructor / Phoenix / LiteLLM**：知道用途即可——instructor 是"结构化 LLM 输出"库（你的 FinalTool 已是同一招的原生版）；Phoenix 是另一个观测工具；LiteLLM 统一多家模型 API + 自带成本追踪。

## 4. LangGraph 专项 · 从零到能读懂

你最不熟，且它和你手写的 `Coordinator` 是**镜像关系**——学它的最大收益不是拿来用，而是**面试时能精准回答"为什么不用它"**。

### 4.1 先破除"它很玄"的错觉

LangGraph 不是什么魔法，就一句话：**把 Agent 的控制流画成一张"带状态、可分支、可循环、可存档"的图。** 你现在是用 `if/while` 手写这张图，它把这张图变成显式的数据结构。

### 4.2 四个核心概念（配你已有的对照）

| LangGraph 概念 | 大白话 | 你项目里的对应物 |
|---|---|---|
| **State（状态）** | 一个贯穿全程的数据包，每个节点读它、改它 | 你在 5 个 Agent 间传递的 artifact（req/cases/raw/diagnosis） |
| **Node（节点）** | 一个普通函数：输入 State，输出对 State 的更新 | 你的 `RequirementAgent.run()` / `AnalysisAgent.run()` 等 |
| **Edge（边）** | 节点之间怎么连。**条件边**=看 State 决定下一站 | 你的 `if diagnosis.need_reproduce: 回执行 else: 去报告` |
| **Checkpointer** | 把 State 存下来，崩了能从断点续跑 | 你手写的 `CheckpointStore` + `resume()` |

一句话总结：**LangGraph = StateGraph（状态图）+ 条件边（分支/循环）+ Checkpointer（续跑）。你的 Coordinator 就是这三样的手写版。**

### 4.3 最小实操（做到某天抽半小时，20 行感受一下）

不接进主项目，单独建个 `learn/langgraph_hello.py` 跑一次，只为建立手感：

```
概念顺序：
1. 定义 State（一个 TypedDict，比如 {count: int}）
2. 写两个 Node 函数（各自把 count +1）
3. 用 StateGraph 把两个节点连起来，加一条"count<3 就回到节点1"的条件边（制造一个循环）
4. compile 后 invoke，观察它循环了几次——这就是你复测循环的极简版
5. 加一个 SqliteSaver 当 checkpointer，中断后 resume，对比你手写的 checkpoint
```

我会在你想学时，把这段真的写出来 + 逐行讲，并**和你 `coordinator.py` 的对应片段并排对比**。

### 4.4 学完你能讲的那句话（面试杀伤力）

> 「我手写的 Coordinator 相当于 LangGraph 的 StateGraph + SqliteSaver。我选择自己写，是因为①硬件在环、长时采集不是 LangGraph 的设计中心；②我想吃透 tool-use 循环和续跑机制。但我清楚框架把状态管理、条件边、checkpointer 都封装好了——**我知道边界在哪：领域控制流我自己写，纯基础设施我会复用**。」

这句"我知道边界在哪"，比"我全自己写"或"我全用框架"都高一档。
